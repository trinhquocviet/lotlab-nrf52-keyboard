# Lot60-BLE Hardware, Mode Switching & Flashing Guide

> **Reference PCB:** Rev.G / Rev.GX — single RGB LED — nRF52810 — on-board CMSIS-DAP
> **Fork:** <https://github.com/trinhquocviet/lotlab-nrf52-keyboard>
> **Upstream Wiki:** <https://wiki.lotlab.org/ble/lot60-ble.html>

---

## 1. Hardware Overview

The Lot60-BLE is a 5×14 (60%) dual-mode Bluetooth/USB keyboard with **two microcontrollers** on each PCB:

| Chip | Role | Flash Tool | Firmware |
|------|------|-----------|----------|
| **nRF52810** (or **nRF52832** variant) | Main controller — BLE, key matrix, LEDs | `pyocd` / `nrfutil` DFU | `.hex` or `.zip` |
| **CH554** | USB interface — HID, UART bridge, CMSIS-DAP debugger | `usbisp` (Linux) / WCH ISP Tool (Windows) | `.bin` |

> **Important:** Always keep nRF52 and CH554 firmware versions in sync when upgrading.

### Default Keyboard Shortcuts & Power Behaviour

- **Boot / Wake from deep sleep:** `Space + U`
- **Clear paired devices:** `Space + E` (or `Fn + R` on fork `v1.2.1.0+`)
- **Manual sleep:** `Fn + CapsLock`
- **Toggle USB / BLE:** `Fn + Tab`
- **Multi-device switch (`v1.2.0.0+`):** `Space + U + Q/W/E` (or `Fn + T/Y/U` on fork `v1.2.1.0+`, up to 3 BLE hosts)
- **Idle timeouts:** Enters slow scan after `15 s`, auto-sleeps after `600 s`

### Status LED Colours (Single RGB LED — `rev_g`)

| Colour | Hex | Meaning |
|--------|-----|---------|
| White | `#FFFFFF` | No connection (idle) |
| Cyan | `#66FFFF` | BLE connected |
| Sky Blue | `#0099FF` | USB connected |
| Orange | `#FF8000` | Charging |
| Green | `#00FF00` | Fully charged |
| Yellow | `#FFFF00` | Passkey input required |
| Pink | `#FF0080` | Passkey sent |
| Purple | `#FF00FF` | Sleeping |

## 2. PCB Revisions & Firmware Compatibility

### Revision Matrix

The build system produces firmware for **8 revision variants** with different GPIO pinouts, MCUs, and LED setups. **Flashing the wrong revision can brick the keyboard.**

| Directory | Board | Chip | LED Config | CMSIS-DAP | DFU Button |
|-----------|-------|------|-----------|-----------|------------|
| `rev_c` | Rev.C | nRF52810 | 1 RGB LED | ✅ Yes | No (Buttonless DFU) |
| `rev_e` | Rev.E | nRF52810 | 1 RGB LED | ❌ No | No (Buttonless DFU) |
| `rev_e_3led` | Rev.E | nRF52810 | 3 status LEDs | ❌ No | No (Buttonless DFU) |
| `rev_f` | Rev.F | nRF52810 | 1 RGB LED | ❌ No | No (Buttonless DFU) |
| `rev_f_3led` | Rev.F | nRF52810 | 3 status LEDs | ❌ No | No (Buttonless DFU) |
| **`rev_g`** | **Rev.G/GX** | **nRF52810** | **1 RGB LED** | **✅ Yes** | **Yes (RESET pin)** |
| `rev_g_3led` | Rev.G/GX | nRF52810 | 3 status LEDs | ✅ Yes | Yes (RESET pin) |
| `rev_g_832` | Rev.G/GX | **nRF52832** | 1 RGB LED | ✅ Yes | Yes (RESET pin) |

### Mismatch Consequences

| Mismatch | Consequence |
|----------|-------------|
| Wrong board family (e.g., `rev_e` on Rev.GX) | Wrong GPIO pins → dead keys, wrong LEDs, broken USB |
| Wrong chip (`rev_g_832` on nRF52810) | Image exceeds 192 KB flash → **won't boot, possible brick** |
| Wrong LED variant (`rev_g_3led` on single-LED PCB) | Keyboard works, but status LED colours are incorrect |

### LED Configuration Details

Defined in `keyboard/lot60-ble/common/common.mk`:
- `THREE_LED_STATUS` unset → builds with `ONE_RGB_LED = yes` and `user_evt.c` (single RGB LED driver)
- `THREE_LED_STATUS = yes` → builds with `THREE_LED_STATUS` and `3led_status.c` (3 discrete LEDs)

### Chip Memory Limits

| Chip | Flash Size | Max Address |
|------|-----------|-------------|
| nRF52810 | 192 KB | `0x30000` |
| nRF52832 | 512 KB | `0x80000` |
| CH554 | 14 KB code | `0x3800` |

## 3. Build System & Firmware Naming

### Toolchain Requirements

| Tool | Version | Purpose |
|------|---------|---------|
| `arm-none-eabi-gcc` | 7-2018-q2-update or GCC 12+ | nRF52 firmware compilation |
| `sdcc` | >= 4.0.0 | CH554 firmware compilation |
| `nrfutil` | Latest | BLE DFU package generation (`.zip`) |
| `mergehex` | Nordic CLI tools | Merge SoftDevice + application into `.hex` |
| `make` | GNU Make | Build orchestration |
| nRF5 SDK | 15.3.0 | Nordic SDK (placed in `SDK/`) |

### Build Commands

```bash
# Build a single revision (e.g., Rev.G/GX single RGB LED)
./scripts/build_lot60ble.sh --revision rev_g

# Build all 8 revisions
./scripts/build_lot60ble.sh

# Build using Docker (no local toolchain required)
./scripts/build_lot60ble.sh --docker
```

### Firmware File Naming Convention

Generated by `keyboard/lot60-ble/Makefile`:

```text
lot60-ble-{revision}-{chip}-{date}-{git_version}.{ext}
```

Example outputs for `rev_g`:

```text
lot60-ble-rev_g-nrf52-2026_06_11-v1.2.0.0.hex   # pyocd flash (merged with SoftDevice)
lot60-ble-rev_g-nrf52-2026_06_11-v1.2.0.0.zip   # BLE DFU package
lot60-ble-rev_g-ch554-2026_06_11-v1.2.0.0.bin   # CH554 USB firmware
```

### GitHub Release Workflow

- Pushing a `v*.*.*.*` tag triggers `.github/workflows/Release.yml`.
- Builds all 8 revisions and uploads up to 24 artifacts (`*.hex`, `*.zip`, `*.bin`).

## 4. Software Mode Switching (No-Jumper / Sealed Case)

When the keyboard is assembled inside its case and physical PCB buttons/jumpers are inaccessible, you can enter every flashing/debug mode over USB using the scripts in `scripts/`.

The scripts use inline PEP 723 metadata and run directly via [`uv`](https://docs.astral.sh/uv/):

```bash
# Install uv if needed
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### 4.1 Accessing On-board CMSIS-DAP Debugger

- **Mechanism:** When running standard firmware over USB, CH554 enumerates as a composite USB device exposing both HID keyboard and DAP-Link/CMSIS-DAP interfaces simultaneously. No mode switch or jumper is needed on Rev.GX.
- **Verify connection:**
  ```bash
  uvx pyocd list
  ```
  A `CMSIS-DAP` probe should appear in the output.

### 4.2 Entering nRF52 BLE DFU Mode (`scripts/enter_dfu.py`)

- **Mechanism:** The nRF5 SDK bootloader checks the `GPREGRET` register (`0x4000051C`) on boot. Writing `0xB1` (`BOOTLOADER_DFU_START`) via CMSIS-DAP and triggering a soft reset forces the nRF52 into BLE DFU mode (`DFUTarg`) without pressing `Space + B` or a physical reset button.
- **Usage:**
  ```bash
  uv run scripts/enter_dfu.py
  ```
  Look for `DFUTarg` in nRF Connect (mobile) or flash a `.zip` package with `nrfutil`.

### 4.3 Entering CH554 USB ISP Mode (`scripts/enter_isp.py`)

- **Mechanism:** In `usb/main.c`, the CH554 firmware listens on Endpoint 3 for a magic packet where byte 2 is `0xF0` and byte 3 is `0x00`. Upon receipt, it disables the watchdog, detaches USB, and jumps to `0x3800` (`isp_enter()`, the built-in CH554 bootloader)—no need to hold the rear K1 button.
- **Usage:**
  ```bash
  uv run scripts/enter_isp.py
  ```
  The keyboard disconnects and re-enumerates as a CH554 ISP device ready for `usbisp`. After flashing `.bin`, it reboots automatically into normal mode.

### 4.4 Alternative: Persistent Virtual Environment

If you prefer a standard `.venv` over on-the-fly `uv run`:

```bash
./scripts/setup_env.sh
source scripts/.venv/bin/activate
```

This installs `hidapi` and `pyocd` from `scripts/requirements.txt`.

## 5. Flashing Methods & Compatibility Checker

### Method 1: `pyocd` (CMSIS-DAP / SWD) — Recommended for Rev.G/GX

Wired flashing via the on-board CMSIS-DAP debugger.

```bash
# Standard flash
./scripts/flash_lot60ble.sh -m pyocd -f lot60-ble-rev_g-nrf52-*.hex

# Full chip erase + flash (for downgrades or clean install)
./scripts/flash_lot60ble.sh -m pyocd -f firmware.hex --erase
```

**Prerequisites:**
- `pyocd` (`pip3 install pyocd` or `uvx pyocd`)
- macOS: `brew install libusb`
- Linux: udev rules (`sudo python3 -m pyocd.udev`)

### Method 2: Bluetooth DFU (`nrfutil` / nRF Connect)

Wireless update over BLE using a `.zip` DFU package.

```bash
./scripts/flash_lot60ble.sh -m dfu -f lot60-ble-rev_g-nrf52-*.zip
```

**Enter DFU mode** (any one of):
- Software: `uv run scripts/enter_dfu.py`
- Keyboard: `Fn + CapsLock` (sleep), then `Space + B` (wake in DFU)
- Hardware: press the `RESET` button on Rev.G/GX

**Mobile DFU:** Open nRF Connect (iOS/Android) → scan & connect to `DFUTarg` → DFU → select `.zip`.

### Method 3: CH554 USB ISP (Linux / Windows)

Updates the CH554 USB bridge controller using a `.bin` image.

```bash
./scripts/flash_lot60ble.sh -m usb -f lot60-ble-rev_g-ch554-*.bin
```

**Enter ISP mode** (either):
- Software: `uv run scripts/enter_isp.py`
- Hardware: unplug USB → hold K1 (rear PCB) → plug USB → release once detected

**Tools:**
- Linux: `usbisp` from [librech551](https://github.com/rgwan/librech551)
- Windows: [WCH ISP Tool](http://www.wch.cn/downloads/WCHISPTool_Setup_exe.html)
- macOS: Not natively supported (use a Linux VM)

### 5-Layer Firmware Compatibility Checker

`scripts/flash_lot60ble.sh` validates firmware before flashing:
1. **Extension vs. method:** `.hex` (pyocd), `.zip` (dfu), `.bin` (usb)
2. **Firmware revision vs. PCB revision:** checks board family, chip, and LED match
3. **Chip type vs. flash method:** blocks cross-chip flashing errors
4. **CMSIS-DAP availability:** warns if target PCB lacks an on-board debugger
5. **Binary verification:** checks Intel HEX addresses (blocks 512 KB nRF52832 images on 192 KB nRF52810) and enforces the 14 KB CH554 `.bin` limit

```bash
# Default PCB is rev_g
./scripts/flash_lot60ble.sh -m pyocd -f firmware.hex

# Specify another PCB revision
./scripts/flash_lot60ble.sh -m pyocd -f firmware.hex -p rev_g_3led

# Bypass checks (use with caution)
./scripts/flash_lot60ble.sh -m pyocd -f firmware.hex --skip-compat
```

### Quick "No-Jumper" Flashing Workflow

1. **nRF52 main firmware (`.hex`):** `./scripts/flash_lot60ble.sh -m pyocd -f <file>.hex` (CMSIS-DAP is always active)
2. **nRF52 BLE DFU (`.zip`):** `uv run scripts/enter_dfu.py` → flash `.zip` via nRF Connect / `nrfutil`
3. **CH554 USB firmware (`.bin`):** `uv run scripts/enter_isp.py` → flash `.bin` via `usbisp` (auto-reboots when done)

## 6. Scripts Reference & Key Source Files

### Scripts Overview

| Script | Purpose |
|--------|---------|
| `scripts/build_lot60ble.sh` | Build firmware from source (single revision or all) |
| `scripts/flash_lot60ble.sh` | Flash firmware with 5-layer compatibility checking |
| `scripts/enter_dfu.py` | Reboot nRF52 into BLE DFU mode via CMSIS-DAP |
| `scripts/enter_isp.py` | Reboot CH554 into USB ISP mode via HID magic packet |
| `scripts/setup_env.sh` | Create a persistent Python `.venv` with `hidapi` & `pyocd` |

### Common Flags

**`build_lot60ble.sh`:** `-r, --revision <rev>` | `-D, --docker` | `-j, --jobs <N>` | `-o, --output <dir>`

**`flash_lot60ble.sh`:** `-m, --method <pyocd|dfu|usb>` | `-f, --file <path>` | `-p, --pcb <rev>` (default: `rev_g`) | `-e, --erase` | `-d, --dfu-device <addr>` | `--skip-compat`

### Key Source Files

| File | Purpose |
|------|---------|
| `keyboard/lot60-ble/Makefile` | Top-level build orchestrator & output naming |
| `keyboard/lot60-ble/common/common.mk` | Hardware revision, LED, and chip selection |
| `keyboard/lot60-ble/common/config.h` | Shared USB IDs, matrix, BLE, and power settings |
| `keyboard/lot60-ble/common/config.rev_g.h` | Rev.G/GX GPIO pin assignments |
| `keyboard/lot60-ble/common/user_evt.c` | Single RGB LED status indicator logic |
| `keyboard/lot60-ble/rev_g/Makefile` | Rev.G build target (`HARDWARE_VERSION = REV_G`) |
| `usb/main.c` / `usb/usb.mk` | CH554 USB bridge, ISP trigger, and build config |
| `.github/workflows/Release.yml` | Automated multi-revision release pipeline |
